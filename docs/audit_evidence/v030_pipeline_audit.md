## Architecture and working behavior

A normalized document is registered in SQLite, raw/normalized provenance persisted, split into chunks, extracted through neo4j-graphrag Prompt 1, resolved by cache/normalization/aliases/Prompt 2, validated, written to Parquet, then optionally MERGEd into Neo4j. Status advances PENDING/PROCESSING -> EXTRACTED -> RESOLVED -> COMMITTED. With no Neo4j RESOLVED is final successful state. JSON checkpoints use temp-file fsync + atomic replace. Per-chunk keys include stable chunk ID, exact rendered prompt/schema/examples, model parameters, extractor type, structured-output/on-error settings. Completed chunks survive sibling failures; at most one additional extraction retry is performed for classified transient errors. These are working safeguards to retain. No second-source process is invoked by this pipeline; source metadata is propagated.

## Runtime evidence limits

Repository contains no real state DB, generated Parquet, retrieval manifests, real runtime logs, or executed notebook output. `docs/test-run.txt` reports 421 stub/offline tests in 86.39 seconds and explicitly says no GPU throughput/provider quality/model accuracy measured (`docs/TEST_RESULTS.md`). `examples/demo_graph.json` is synthetic. Therefore average docs/entity, chunks/doc, elapsed/doc, candidates/accepted facts, expansion yield, full-text rate/provider and frontier breadth cannot be empirically estimated from this checkout. Runtime/breadth forecasts must be scenario calculations with stated assumptions.

Actual checked-in configuration: `config/base.yaml:52` sets `Qwen/Qwen3.8-27B`, not user’s practical Qwen3-4B model. Colab overlay inherits it and sets 200 minutes (`config/colab_professor_expand.yaml:23`); base runtime is 110 minutes. The notebook is an unexecuted Markdown cell sketch that explicitly injects MAX_DOCUMENTS=100 and FRESH_RUN=True. No measured T4 run proves another model. Recommended explicit Colab overlay should set Qwen/Qwen3-4B-Instruct-2507 and 110 minutes, concurrency conservative, avoid fixed 100 notebook override, report actual metrics on first run.

For 2000-character chunks with 200 overlap (current defaults), approximate extraction chunks = ceil(max(0, characters-200)/1800), minimum one for nonempty text. A 10k-char article therefore takes about six extraction calls, plus up to one alias call per new type and ceil(tier/risky candidate count / 10) entailment calls plus optional repairs. No reliable tokens/sec evidence available. Full-text retrieval must therefore be coupled to bounded excerpt/chunk handling and measured runtime scheduling, not just larger document ceilings.

## Frontend inventory (unchanged)

Self-contained HTML/CSS/JS viewer with JSON shape checks, source escaping, SVG tiers, seed filter, evidence inspector, offline file loading and SVG/JSON save. It defaults to one source and explicitly states source counts are not independence/confidence. Rendering caps 300 nodes/1000 edges and explains truncation. UI seed-path filtering traverses all suppliesTo rather than backend expansion-relevant core; frontend changes expressly forbidden for this task, so exporter must expose clear backend core metadata without relying on UI filtering for correctness.

## Dependency retry inspection

Installed primary library source confirms `OpenAILLM.__init__` passes client kwargs to OpenAI; omitted client retry policy uses the SDK default two retries. `LLMInterface` assigns `DEFAULT_RATE_LIMIT_HANDLER`, whose `RetryRateLimitHandler` defaults to three attempts. Combined with extract_graph two outer attempts, a 429 can generate up to 18 HTTP attempts per chunk (3 SDK attempts × 3 wrapper attempts × 2 extraction attempts). Confirmed high runtime/budget risk under an unhealthy or overloaded local endpoint. Set explicit client max_retries=0 and rate-limit max_attempts=1 while retaining bounded extraction retry; log actual retry policy. One runtime request timeout is not a whole-document deadline.

Baseline owned offline tests: `python -m pytest -q -m "not integration" tests/test_pipeline.py tests/test_pipeline_reliability.py tests/test_ingest.py tests/test_upgrade.py tests/test_validation.py` -> 42 passed in 6.62s. No live experiment run.

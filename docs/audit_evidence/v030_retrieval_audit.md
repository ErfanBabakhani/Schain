Additional confirmed defects:

1. **High retrieval runtime waste:** `_add_full_text` fetches *all raw results* at :360, before URL dedup :380 and relevance/ranking. Eight queries × (12 Google News + 12 GDELT + 12 general-web + 5 Wikipedia) = up to 328 rows/entity. Same article gets many network fetches. Canonicalization is later serial per result (:94) with HEAD+GET (up to 16s) and not persisted after enrichment; resume can repeat it. Need early normalized URL dedup, bounded direction-ranked fetch shortlist, concurrency-aware canonical resolution and canonical metadata persistence.
2. **High retry/checkpoint hole:** `state.record_search(... DONE)` at retrieve.py:352–353 occurs before full-text and search Parquet flush :360–361. Interruption can mark query done with no cached result rows, permanently skipping retrieval on resume. Persist raw rows before DONE or add completed batch consistency check; zero-result successful queries need explicit success count.
3. **Medium provider error attribution:** providers `get_json/get_text` return `None` on HTTP failure and provider `search` returns `[]`; `_run_query` returns empty and `record_search` marks DONE. HTTP errors are indistinguishable from genuine zero hits and not retried. `test_a_failing_provider...` only covers raised exceptions, not ordinary HTTP 429/500 handled inside helpers. Use bounded provider exceptions / status metadata while preserving standalone graceful behavior.
4. **High query escaping bug:** google_news.py:42 and general_web.py:87 take `httpx.QueryParams({'q':query})['q']` (decoded value) and interpolate into raw URL. An entity `A&B` produces q=`"A`, and `#` truncates rest into fragment. Use `str(httpx.QueryParams(...))` / params. Reproduced offline with `httpx.URL`.
5. **Medium audit double-counting:** manifest `update_by_url` marks every duplicate provider/query row PROCESSED. `summary.sent_to_prompt1` counts rows (:153), not actual unique processed documents. One processed URL from two providers reports two calls. Add selected/processed document identity and explicit credited row; preserve raw candidate totals separately.
6. **Medium cache rehydration:** `load_search_results` directly hydrates pandas missing values (:224–226). When columns added across schema versions, NaN becomes truthy `text/canonical_source_url`, corrupting content_source or URI handling. Convert pandas scalar nulls to None; preserve old schema.
7. **Medium origin mismatch:** first `is_relevant` requires canonical-name substring (:176), then later origin filter expands configured aliases (:407–410). Thus a legitimate alias-only page may be rejected before alias-aware stage. Boundaryless substring `mentions_entity` also accepts `BMW` in `BMWi7`/other strings. Share conservative boundary matching/alias variants across prefilters and ranker.
8. **Low extraction limit:** base.fetch_article_text excludes HTML tables. Supplier tables/annual reports can be useful, but turning all tables on indiscriminately increases noise/chunks. Candidate for small targeted follow-up rather than broad change; full-text HTTP PDF extraction currently absent.
9. **Low Wikipedia redirects:** `_fetch_extracts` maps extracts by canonical page title while `search` matches original hit titles. Redirected hits can lose available full text; snippet HTML also remains if extract unavailable.
10. **Low stale docs:** PROJECT_DECISIONS claims 13 default seeds, Tier 6, Qwen 27B; effective current expansion file has four seeds and Tier 5. Already root config audit scope.

Offline reproductions (no live requests): publisher remains after make_document with repeated Google RSS description; generic dashed full-text drops supply clause; `A&B` query round-trip corrupts; manifest reports two Prompt-1 documents for one URL.

Recommended grouped plan for this scope:
- MUST: canonicalization before fetch; publisher metadata/clean fallback; early URL fetch dedup; query encoding; search checkpoint ordering; accurate selected/processed provider provenance.
- SHOULD: optional capped exact-title recovery; cached resolution; null-safe legacy Parquet loading; bounded pre-ranked fulltext pool; alias-aware filter.
- OPTIONAL: clarify legacy independence labels without schema migration; Wikipedia redirect fix; targeted table/PDF fetch support later.
